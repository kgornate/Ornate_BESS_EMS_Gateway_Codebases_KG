# Phase 4 — Flutter control performance

This patch fixes two measured field issues without changing BMS/PCS registers,
write sequences, safety verification or solar/ABB decoding:

1. Gateway restart was proportional to the 10 GB telemetry database because
   `SQLiteStore` scanned the full telemetry table before Uvicorn could bind.
   Record/size counters are now persisted transactionally and loaded in O(1).
   Installation performs one final exact counter seed while the gateway is
   stopped.
2. Flutter's cache-only all-pair view could wait behind the main gateway cache
   lock while poll finalization performed alarm/storage work. A separate,
   immutable control cache is now published after every poll. Flutter and the
   scheduler read this cache without hardware I/O and without taking the main
   plant-cache lock.

## Safety scope

- No Modbus register, function code, sign convention or control sequence is changed.
- No automatic command is generated by installation or verification.
- Verification is read-only/mock-only.
- The site scheduler must be inactive during installation.

## Install

```sh
cd /root/kinetics_phase4_flutter_control_performance_20261107_v2
CONFIRM_IDLE=YES bash install_phase4_flutter_control_performance.sh
```

The one-time exact database-counter seed can take several minutes on the field
SD card. Subsequent gateway restarts no longer repeat that scan.

## Verify

```sh
bash verify_phase4_flutter_control_performance.sh
```

## Roll back

```sh
bash rollback_phase4_flutter_control_performance.sh /root/kinetics_phase4_flutter_control_performance_backup_TIMESTAMP.tar.gz
```
